MemArtsStore
============

MemArtsStore Basic Principles
-----------------------------

MemArtsStore is a high-availability write cache service. It mainly provides remote shuffle service for big data applications. During the execution of big data applications, a large amount of shuffle data is generated. If shuffle data is directly written to the remote storage service layer such as OBS or EVS and then read from the storage service layer, the performance of big data applications will greatly deteriorate. The current solution is to deploy big data applications on compute servers with local disks. The generated shuffle data is directly written to and then read from local disks. While this method improves the performance of big data applications compared to OBS/EVS, it introduces the following problems:

-  Low deployment flexibility: Big data applications can be deployed only on compute servers with local disks. As a result, cloud vendors must build and maintain such special servers.
-  Low reliability: The reliability and availability are not guaranteed for shuffle data stored on local disks. If a local disk is faulty, shuffle data will be lost. As a result, data fails to be fetched during Reduce, and big data tasks need to be recalculated.
-  Low performance: Each Mapper can only write the shuffle data generated by itself to the disk of the local node. When the Reducer is running, it needs to obtain shuffle data from massive Mapper nodes. As a result, a large number of small I/Os are generated, and the performance is poor.

MemArtsStore can address these problems. Firstly, by using MemArtsStore to store shuffle data, big data applications no longer require servers with local disks. Secondly, MemArtsStore provides a multi-replica mechanism to ensure high availability of shuffle data. Thereby, the failure of a single node will not cause the loss of shuffle data. Finally, MemArtsStore aggregates data in the same partition to eliminate small I/Os and improve shuffle performance.

MemArtsStore consists of StoreMaster, StoreWorker, StoreSidecar, and StoreClientProxy instances.

-  StoreMaster creates and manages the lifecycle of spaces and partitions.
-  StoreWorker reads and writes data in partitions.
-  StoreSidecar provides capabilities such as MemArtsStore service monitoring and collection, and service startup and stopping.
-  StoreClientProxy reduces the number of connections used by MemArtsStore so that MemArtsStore can be used in a large-scale cluster.

Relationship Between MemArtsStore and Other Components
------------------------------------------------------

MemArtsStore replaces the native shuffle service of Spark to store shuffle data for Spark. The Map task of Spark writes shuffle data to the Store, and the Reduce task reads shuffle data from the Store.
